# Phase 7: explanations and calibrated intervals

Generated by `make train` (`src/bsp/explain/`). Everything is out-of-sample (walk-forward folds); the FY2024-25 and FY2025-26 hold-out and the live year were not touched. Nothing here changes a forecast or rank. Nothing is investment advice.

## Method

- **SHAP / attributions** (`reports/shap_values_sector.csv`, `reports/shap_values_stock.csv`): one row per prediction and feature. LightGBM models use SHAP's TreeExplainer, for the expected-excess-return regressor (`target = expected_return`) and for the ranker's raw score (`target = rank_score`). The Bayesian model's posterior-mean predictor is exactly additive (sector intercept + surprise slope x surprise + controls), so its attributions are exact; the blend and stack apply their own weights to their components' attributions. Each row set satisfies baseline + sum of contributions = forecast (check below).
- **Three reasons** (`bsp/explain/reasons.py`, wording in `config/feature_reasons.json`): the three features with the largest absolute contribution to the expected excess return, with the feature's value, the effect in percentage points and a source reference. The baseline is never a reason. The reasons explain the expected excess return that the interval wraps; the rank comes from the ranker, whose order usually but not always agrees.
- **Intervals** (`bsp/explain/conformal.py`, MAPIE split conformal, 80%): for each test budget, the calibration errors are all earlier out-of-sample forecasts of the same model whose 12m label was known on its day 0. With fewer than 3 such budgets the interval is the model's own out-of-fold residual interval (`interval_method` in `reports/predictions_detail.csv`). Conformal guarantees assume exchangeable errors, which returns over time are not, so coverage is checked, not assumed.
- **Table:** `data/csv/predictions.csv` (loaded into the `predictions` table by `make load`) has `model_version, entity, budget_id, expected_excess, p10, p90, p_beat, rank, top_reasons` (a JSON list of three strings). `rank` is 1 = best within the model and budget over all entities. `model_version` names the model, seed and a hash of the input CSVs.

## Limitations

- The attributions describe the model, not the economy: a high contribution means the fitted model leaned on that feature, not that the feature caused the return. With 12 sector test years, the models themselves are weak (see `reports/models.md`).
- Features the model could not see (missing values) are reported as not available; LightGBM still routes them down a default branch, so a missing value can carry a contribution.
- Year-level features (fiscal deficit, subsidies, macro series) take the same value for all sectors in a budget, so a tree can use them as a stand-in for the year; their reasons say what the model used, not that the deficit moved a sector's return.
- The FPI, speech and fundamentals families are mostly missing, so they rarely appear among the top three.
- `credibility_pct` has extreme outliers in some early rows (up to 43,964%), which can dominate a reason; this is a data issue recorded here, not changed.
